# 多平台并行爬取 - 使用手册

## 功能概述

当一批待检测的链接涉及多个平台（如抖音、B站、快手等）时，系统自动为每个平台启动独立的浏览器实例并行处理，显著提升批量爬取的整体速度。

---

## 配置方式

在 `config/base_config.py` 中控制开关：

```python
# 多平台并行处理开关（默认开启）
URLCHECK_PARALLEL_PLATFORMS = True
```

- `True`：多平台同时处理（推荐）
- `False`：回退为逐平台顺序处理

---

## 使用场景

### 自动触发条件

当满足以下**全部条件**时，系统自动启用并行模式：

1. `URLCHECK_PARALLEL_PLATFORMS = True`
2. 当前批次的 URL 涉及 **2个或以上**不同平台

若仅有1个平台的链接，则无需并行，自动走顺序模式。

### 涉及的接口（无需更改调用方式）

- `POST /api/v1/check/batch` — 批量检测
- `POST /api/v1/check/upload` — 文件上传检测
- `POST /api/v1/check/mysql` — MySQL 数据源检测
- CLI 模式：`uv run python main.py --type url_check`

## 使用示例

### 示例1：批量接口

```json
POST /api/v1/check/batch
{
  "urls": [
    "https://www.douyin.com/video/7628682927572997561",
    "https://www.bilibili.com/video/BV1godYBUE3f",
    "https://www.kuaishou.com/short-video/3xrenpyd68isk2q",
    "https://weibo.com/1806503894/QEoCgiKVs",
    "https://www.toutiao.com/article/7489803498200687115"
  ],
  "mode": "both"
}
```

此请求涉及5个平台，系统会同时启动5个浏览器实例并行处理。

## 关闭并行的场景

以下场景建议关闭并行处理（设置 `URLCHECK_PARALLEL_PLATFORMS = False`）：

| 场景 | 原因 |
|------|------|
| 服务器内存不足（< 4GB） | 多个浏览器实例占用大量内存 |
| 需要严格控制带宽 | 并行时多个浏览器同时下载资源 |
| 调试单平台问题 | 顺序模式日志更清晰 |

---

## 注意事项

1. **风控安全**：每个平台内部仍逐条顺序爬取，单平台同一时间只有一个请求
2. **资源消耗**：N个平台 = N个浏览器实例，内存占用约 200-400MB/个
3. **Cookie池兼容**：并行模式下每个平台独立使用自己的Cookie，互不影响
4. **任务取消**：用户终止任务时，所有平台的浏览器都会被正确关闭
