# 零互动检测优化 - 原理说明

## 问题背景

许多帖子的转赞评全为 0（账号禁止互动、帖子无热度等），但接口数据结构完全正常。原先的逻辑会对这些帖子触发 AI 提取，浪费大量 token 和时间。

## 解决方案

在调用 AI 之前增加三层判断，只有在确定平台接口可能变动时才触发 AI。

## 架构设计

### 涉及文件

| 文件 | 职责 |
|------|------|
| `tools/ai_field_mapper.py` | 三层兜底主逻辑，在 `extract_metrics()` 中实现 |
| `tools/platform_health_checker.py` | 基准帖子检测、缓存管理、诊断报告生成 |
| `tools/fallback_field_map.py` | 各平台硬编码字段路径，新增 `title` 路径 |
| `config/base_config.py` | 基准帖子配置、缓存 TTL |

### 执行流程

```
extract_metrics(platform, raw_json, health_checker, task_info)
  │
  ├── 硬编码提取 → fallback_extract()
  │
  ├── 指标充足？ → 返回（跳过 AI）
  │
  ├── 指标全0 → 进入三层兜底
  │   │
  │   ├── Layer 1: has_content_fields(result)
  │   │   检查 author/title 是否非空
  │   │   → 非空 → last_method="硬编码(零互动)" → 返回
  │   │
  │   ├── Layer 2: health_checker(platform)
  │   │   调用 check_benchmark() 检测基准帖子
  │   │   → 缓存命中？直接用缓存结果
  │   │   → 缓存失效？用同一个 client 请求基准帖子
  │   │   → 基准正常 → last_method="硬编码(零互动-基准验证)" → 返回
  │   │
  │   └── Layer 3: _ai_diagnostic_extract()
  │       AI 提取 + 诊断 prompt
  │       → 分离 JSON 结果和诊断文本（---DIAGNOSIS--- 分隔）
  │       → generate_diagnostic_report() 写入文件
  │       → last_method="AI(诊断)" → 返回合并结果
```

### 缓存机制

```python
_benchmark_cache = {
    "wb": {"healthy": True, "checked_at": 1715510400.0},
    "dy": {"healthy": True, "checked_at": 1715510500.0},
}
```

- 全局字典，进程内共享
- TTL 由 `BENCHMARK_CACHE_TTL_SECONDS` 控制（默认 1800 秒）
- 缓存失效后下次请求自动刷新

### AI 诊断 Prompt

在标准提取 prompt 后追加诊断任务，要求 AI：
1. 分析 JSON 中互动数据的字段名和路径
2. 判断指标全 0 的可能原因
3. 给出硬编码路径修复建议

AI 返回格式：先输出提取的 JSON，然后用 `---DIAGNOSIS---` 分隔符后输出纯文本诊断。

### 依赖注入

`health_checker` 参数通过闭包注入，调用方负责提供能访问平台 API 的 client：

```python
async def _health_check(plat):
    from tools.platform_health_checker import check_benchmark
    return await check_benchmark(plat, client, self._fetch_detail)

metrics = await ai_mapper.extract_metrics(
    platform, raw_json, health_checker=_health_check, task_info=info
)
```

这样 `ai_field_mapper` 不直接依赖浏览器客户端，保持模块解耦。
