# 服务器无界面登录方案

> 适用场景：Linux 无图形化界面的服务器部署，无法直接扫码登录。

---

## 方案对比

| 方案 | 适用场景 | 难度 | 持久性 | 推荐指数 |
|------|---------|------|--------|---------|
| A. 本地扫码→上传Cookie目录 | 首次部署 | ★☆☆ | Cookie有效期内 | ⭐⭐⭐⭐⭐ |
| B. Cookie字符串直接注入 | 临时使用/单平台 | ★☆☆ | 手动更新 | ⭐⭐⭐ |
| C. VNC远程桌面扫码 | Docker/K8s环境 | ★★☆ | Cookie有效期内 | ⭐⭐⭐⭐ |
| D. Cookie池自动轮换 | 长期无人值守 | ★★★ | 自动管理 | ⭐⭐⭐⭐⭐ |

---

## 方案A：本地扫码 → 上传Cookie目录（推荐）

**原理**：在本地有图形界面的电脑上完成各平台扫码登录，Playwright 会将 Cookie/LocalStorage 保存到 `browser_data/` 目录。然后把该目录上传到服务器。

### 步骤

1. **本地完成各平台登录**

```bash
# 确保关闭 headless 模式（需要弹出浏览器窗口扫码）
# config/base_config.py:
#   HEADLESS = False
#   SAVE_LOGIN_STATE = True
#   ENABLE_CDP_MODE = True  （或 False，按你的习惯）

# 依次对每个平台跑一次，让浏览器弹出并扫码登录
python main.py --type url_check --urlcheck_source file --urlcheck_file test_url.txt
```

每个平台第一次运行时会弹出浏览器和二维码，用手机扫码登录即可。
登录成功后 Cookie 会保存在：

- CDP 模式：`browser_data/cdp_{platform}_user_data_dir/`
- Playwright 模式：`browser_data/{platform}_user_data_dir/`

2. **打包上传到服务器**

```bash
# 本地打包
tar -czf browser_data.tar.gz browser_data/

# 上传到服务器
scp browser_data.tar.gz user@server:/path/to/MediaCrawler/

# 服务器解压
cd /path/to/MediaCrawler
tar -xzf browser_data.tar.gz
```

3. **服务器配置**

```python
# config/base_config.py
HEADLESS = True          # 服务器无界面，必须 headless
SAVE_LOGIN_STATE = True  # 保持登录状态
ENABLE_CDP_MODE = False  # 服务器用 Playwright 模式（更稳定）
```

4. **安装 Playwright 浏览器**

```bash
# 服务器上安装 Playwright 依赖的 Chromium
playwright install chromium
playwright install-deps chromium
```

### Cookie 过期处理

各平台 Cookie 有效期不同（通常 7-30 天），过期后需要：
- 在本地重新扫码登录
- 重新上传 `browser_data/` 目录
- 或者使用方案D（Cookie池）实现自动轮换

## 方案B：Cookie字符串直接注入

**原理**：从浏览器开发者工具(F12)手动导出 Cookie 字符串，通过配置注入。

### 步骤

1. **在浏览器中登录目标平台**（如抖音），按 F12 打开开发者工具

2. **复制 Cookie**
   - 切换到 `Application` → `Cookies`
   - 或在 `Network` 面板随便点一个请求，复制 `Cookie` 请求头的完整值

3. **配置注入**

```python
# config/base_config.py
LOGIN_TYPE = "cookie"
COOKIES = "sessionid=xxx; passport_csrf_token=yyy; ..."
```

### 局限

- 每个平台的 Cookie 格式不同，一次只能配置一个平台
- Cookie 过期需要手动重新导出
- 不适合多平台批量处理场景

## 方案C：VNC远程桌面扫码

**原理**：在 Docker 容器中安装 VNC 服务，通过远程桌面连接到容器内的图形界面完成扫码。

### Docker Compose 示例

```yaml
version: "3.8"
services:
  mediacrawler:
    build: .
    ports:
      - "8000:8000"   # FastAPI 服务
      - "5900:5900"   # VNC 端口
    environment:
      - HEADLESS=false  # 首次登录时关闭 headless
      - DISPLAY=:99
    volumes:
      - ./browser_data:/app/browser_data
    command: >
      bash -c "
        Xvfb :99 -screen 0 1920x1080x24 &
        x11vnc -display :99 -forever -nopw -rfbport 5900 &
        sleep 2
        python main.py --type url_check --urlcheck_source file --urlcheck_file test_url.txt
      "
```

### 依赖安装（Dockerfile 中添加）

```dockerfile
RUN apt-get update && apt-get install -y \
    xvfb \
    x11vnc \
    fluxbox \
    && rm -rf /var/lib/apt/lists/*
```

### 使用流程

1. 启动容器：`docker-compose up -d`
2. 用 VNC 客户端（如 RealVNC Viewer）连接 `服务器IP:5900`
3. 在远程桌面中完成扫码登录
4. 登录成功后修改配置为 `HEADLESS=true`，重启容器

### 适用场景

- K8s/Docker 环境首次登录
- 不方便在本地操作时
- 需要在服务器上直接完成登录

## 方案D：Cookie池自动轮换（长期无人值守推荐）

**原理**：预先收集多个账号的 Cookie，存储在文件或数据库中。程序运行时自动从池中获取有效 Cookie，失效时自动切换。

### 配置

```python
# config/base_config.py
ENABLE_COOKIE_POOL = True         # 启用Cookie池
COOKIE_POOL_SOURCE = "file"       # "file" 或 "db"
COOKIE_POOL_FILE = "config/cookie_pool.json"
COOKIE_AUTO_SWITCH = True         # Cookie失效自动切换
COOKIE_MAX_FAILURES = 3           # 连续失败N次标记失效
```

### Cookie 收集方法

1. 准备多个账号（每个平台2-3个即可保证高可用）
2. 在本地逐一登录，从浏览器 F12 导出 Cookie
3. 按格式写入 `config/cookie_pool.json`

```json
{
  "dy": [
    {"id": "dy_01", "cookie": "sessionid=xxx;...", "note": "抖音账号1"},
    {"id": "dy_02", "cookie": "sessionid=yyy;...", "note": "抖音账号2"}
  ],
  "bili": [
    {"id": "bili_01", "cookie": "SESSDATA=xxx;...", "note": "B站账号1"}
  ]
}
```

### 工作机制

1. 启动时加载 Cookie 池
2. 每个平台从池中取第一个有效 Cookie
3. API 调用失败时自动轮换到下一个
4. 连续失败 N 次后标记该 Cookie 为失效
5. 所有 Cookie 耗尽时记录错误日志

详细实现参见 `proxy/cookie_pool.py`。

---

## 补充：是否可以用 Redis？

**可以**，Redis 适合以下场景：

- **多实例部署**：多个爬虫进程/容器共享同一个 Cookie 池
- **实时状态同步**：某个实例发现 Cookie 失效，其他实例立即感知
- **分布式锁**：避免多个实例同时使用同一个 Cookie

当前实现使用本地 JSON 文件，适合单机部署。如果后续需要扩展到多机分布式，可以将 `COOKIE_POOL_SOURCE` 改为 `"redis"`，并实现对应的 Redis 存储后端。
