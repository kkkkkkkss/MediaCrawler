# 零互动检测优化 - 使用手册

## 功能说明

当帖子的点赞、评论、播放量全为 0 时，系统会自动启用三层兜底机制，避免不必要的 AI 调用，节省 token 和时间。

## 默认行为

此功能**默认启用**，无需额外配置。只要使用 `hardcode_first` 提取模式（默认值），三层兜底就会自动生效。

## 触发条件

当硬编码提取的 `praise_count`、`reply_count`、`visit_count` 全部为 0 或 null 时触发。

## 三层兜底行为

1. **第一层 - 检查 author/title**：如果作者名或标题非空，说明接口返回了数据，帖子只是没有互动 → 跳过 AI
2. **第二层 - 基准帖子验证**：用预配置的高热帖子验证平台接口是否正常 → 正常则跳过 AI
3. **第三层 - AI 诊断提取**：基准也异常，说明平台接口可能变动 → 调用 AI 并生成诊断报告

## 基准帖子配置

在 `config/base_config.py` 中修改 `PLATFORM_BENCHMARK_POSTS`：

```python
PLATFORM_BENCHMARK_POSTS = {
    "dy": {"url": "https://www.douyin.com/video/xxx", "content_id": "xxx"},
    "ks": {"url": "https://www.kuaishou.com/short-video/xxx", "content_id": "xxx"},
    # ...
}
```

**要求**：选择确认有效、互动数据充足的帖子，定期检查并更新。

## 缓存配置

基准帖子检测结果会缓存 30 分钟，避免频繁请求：

```python
BENCHMARK_CACHE_TTL_SECONDS = 1800  # 秒，默认30分钟
```

## 诊断报告

当第三层触发时，诊断报告自动生成到 `data/diagnostics/{平台}_{时间戳}.md`，包含：

- 硬编码提取结果
- AI 提取结果
- AI 诊断摘要（接口结构变动分析）
- 原始 JSON 片段

## 日志识别

服务端日志中可通过以下关键字识别兜底行为：

- `第一层兜底: author/title 非空` → 跳过 AI
- `第二层兜底: 基准帖子正常` → 跳过 AI
- `第三层兜底: 启动 AI 诊断提取` → 调用了 AI

提取方式标记：`硬编码(零互动)` / `硬编码(零互动-基准验证)` / `AI(诊断)`
