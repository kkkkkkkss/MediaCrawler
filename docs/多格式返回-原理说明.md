# 多格式返回 - 原理说明

## 设计思路

在任务执行过程中，将原始结果数据保存到 `TaskInfo` 对象中，任务完成后按需序列化为不同格式。

## 架构设计

### 涉及文件

| 文件 | 职责 |
|------|------|
| `api/task_manager.py` | `TaskInfo` 新增 `result_data` 和 `comments_data` 字段 |
| `api/service.py` | 任务完成后将结果数据存入 TaskInfo |
| `api/routes.py` | 新增 JSON 结果端点、评论端点 |
| `store/url_check_json_store.py` | JSON 格式序列化 |
| `store/url_check_comment_export.py` | 评论 JSON/Excel 导出 |
| `api/schemas.py` | `TaskJsonResultResponse`、`TaskCommentsResponse` 响应模型 |

### 数据流

```
任务执行
  │
  ├── crawler._all_results  →  info.result_data（原始结果列表）
  │                              │
  │                              ├── GET /result/json → results_to_json_data() → JSON 响应
  │                              ├── GET /result?format=json → generate_json_file() → 文件流
  │                              └── GET /result?format=excel → 已有 Excel 文件 → 文件流
  │
  └── row["_comments"]     →  info.comments_data（按作品分组的评论）
                                 │
                                 ├── GET /comments → JSON 响应
                                 ├── GET /comments/download?format=json → JSON 文件流
                                 └── GET /comments/download?format=excel → Excel 文件流
```

### TaskInfo 数据结构扩展

```python
class TaskInfo:
    # 原有字段...
    result_data: list        # _all_results 的引用，每个元素是行字典
    comments_data: list      # [{content_url, content_id, platform, comments: [...]}]
    callback_url: str        # 任务级回调地址
```

### JSON 序列化流程

`results_to_json_data()` 负责将内部行字典转换为标准化 JSON 结构：

1. 从 `_metrics` 中取指标数据
2. 调用 `_extract_author()`、`_extract_title()`、`_detect_content_type()` 补充字段
3. 组装为前端友好的扁平对象

### 评论数据收集

在 `_fetch_and_store_comments()` 中，抓取到评论后：

1. 用平台特定的 converter 函数格式化每条评论
2. 存入 `row["_comments"]` 列表
3. 任务完成后，`_collect_comments_data()` 从所有 row 中收集评论，按作品分组
4. 存入 `info.comments_data`

### 端点设计

- `/result/json`：直接返回 JSON 响应体，不生成文件
- `/result?format=json`：每次请求时生成 `.json` 文件并返回文件流
- `/result?format=excel`：返回已有的 Excel 文件流
- `/comments` 和 `/comments/download` 类似逻辑
