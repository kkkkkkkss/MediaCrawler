# 回调机制 - 原理说明

## 设计思路

采用"全局默认 + 任务级覆盖"模式，任务完成后由 TaskManager 的 worker 自动触发回调，不阻塞主流程。

## 架构设计

### 涉及文件

| 文件 | 职责 |
|------|------|
| `api/callback.py` | 回调核心逻辑（发送、重试、地址解析） |
| `api/task_manager.py` | worker 中触发回调 |
| `config/base_config.py` | 全局回调配置项 |
| `api/schemas.py` | 各请求模型增加 `callback_url` 字段 |
| `api/routes.py` | 回调配置查看/更新端点、传递 callback_url |
| `frontend/src/views/CallbackSettings.vue` | 前端全局配置页 |

### 回调触发流程

```
TaskManager.worker_loop()
  │
  ├── await coro_factory(info)     # 执行任务
  │
  ├── info.status = "completed"    # 标记完成
  │
  └── trigger_task_callback(info)  # 触发回调
        │
        ├── resolve_callback_url()
        │   优先级：info.callback_url > config.CALLBACK_URL
        │   → 都没有则跳过
        │
        ├── send_callback(url, "task_completed", ...)
        │   → 主结果 JSON
        │
        └── send_callback(url, "comments_ready", ...)
            → 评论 JSON（如果有）
```

### 地址解析逻辑

```python
def resolve_callback_url(task_callback_url):
    # 1. 任务级：提交时传的 callback_url
    if task_callback_url and task_callback_url.strip():
        return task_callback_url.strip()
    
    # 2. 全局配置：CALLBACK_ENABLED + CALLBACK_URL
    if config.CALLBACK_ENABLED and config.CALLBACK_URL:
        return config.CALLBACK_URL.strip()
    
    # 3. 不回调
    return None
```

### 重试机制

```python
max_retries = config.CALLBACK_MAX_RETRIES  # 默认 3
retry_intervals = config.CALLBACK_RETRY_INTERVALS  # [5, 15, 30]

for attempt in range(max_retries + 1):
    try:
        resp = await client.post(url, json=payload)
        if 200 <= resp.status_code < 300:
            return True  # 成功
    except Exception:
        pass  # 网络异常
    
    if attempt < max_retries:
        await asyncio.sleep(retry_intervals[attempt])

return False  # 全部失败
```

### Payload 结构

```python
payload = {
    "event": "task_completed",     # 事件类型
    "task_id": info.task_id,       # 任务 ID
    "status": info.status,         # 任务状态
    "timestamp": "ISO8601 UTC",    # 发送时间
    "data": { ... },               # 完整结果数据
}
```

主结果的 `data` 结构与 `GET /result/json` 返回的一致。
评论的 `data` 结构与 `GET /comments` 返回的一致。

### 运行时配置更新

`POST /callback/config` 直接修改 `config` 模块的属性值：

```python
config.CALLBACK_ENABLED = req.enabled
config.CALLBACK_URL = req.url
```

这是运行时生效的，重启后恢复 `base_config.py` 中的默认值。如需持久化，需手动修改配置文件。

### 安全考虑

当前版本不支持回调认证（无 Token、签名）。如果回调地址需要认证，建议：
1. 在回调 URL 中嵌入 Token（如 `https://xxx.com/callback?token=abc`）
2. 接收方通过 URL 参数验证
3. 后续版本可扩展 `callback_headers` 配置
