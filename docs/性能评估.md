# 批量爬取性能评估

## 实测基准数据

### 测试环境

- 系统：Windows 10
- 内存：16GB
- 网络：100Mbps
- Playwright headless 模式

### 各平台单条URL处理耗时（实测）


| 平台           | 单条耗时(秒) | 主要耗时环节                                           |
| ------------ | ------- | ------------------------------------------------ |
| 头条 (toutiao) | ~8-10   | goto页面(3s) + 等待渲染(3s) + DOM提取(2s) + 二次确认(如需,+6s) |
| 抖音 (dy)      | ~5-6    | API调用(2s) + Cookie验证(1s) + 间隔(2s)                |
| B站 (bili)    | ~5-6    | API调用(2s) + 间隔(2s) + 数据解析(1s)                    |
| 快手 (ks)      | ~5-6    | API调用(2s) + 间隔(2s) + 数据解析(1s)                    |
| 微博 (wb)      | ~5-6    | API调用(2s) + 间隔(2s) + 数据解析(1s)                    |


**浏览器启动开销**：每个浏览器首次启动约 3-5 秒。

**HTTP预检**：每条URL约 0.5-1秒，所有URL并行预检（不显著增加总时间）。

## 性能预估模型

### 公式

```
总耗时 ≈ max(各平台耗时)

单平台耗时 = ceil(该平台URL数 / 该平台并发数) × 单条耗时 + 浏览器启动(5s×并发数)
```

---

## 场景预估：500 条链接

### 场景一：500条全部是头条（无Cookie平台）


| 配置        | 并发数 | 预估耗时  | 说明               |
| --------- | --- | ----- | ---------------- |
| 不开并发      | 1   | ~75分钟 | 500 × 9s = 4500s |
| toutiao=2 | 2   | ~38分钟 | 250 × 9s + 启动开销  |
| toutiao=3 | 3   | ~25分钟 | 167 × 9s         |
| toutiao=4 | 4   | ~19分钟 | 125 × 9s         |
| toutiao=5 | 5   | ~15分钟 | 100 × 9s         |


### 场景二：500条全部是抖音（需要Cookie，池中3个）


| 配置   | 并发数 | 实际并发         | 预估耗时        |
| ---- | --- | ------------ | ----------- |
| dy=1 | 1   | 1            | ~50分钟（6s一个） |
| dy=2 | 2   | 2            | ~25分钟       |
| dy=3 | 3   | 3            | ~17分钟       |
| dy=5 | 5   | 3(受Cookie限制) | ~17分钟       |


### 场景三：500条平均分配5个平台（每平台100条）

#### 仅跨平台并行（各平台并发=1）

```
各平台耗时：
  dy: 100 × 6s = 600s
  bili: 100 × 6s = 600s
  ks: 100 × 6s = 600s
  toutiao: 100 × 9s = 900s
  wb: 100 × 6s = 600s

总耗时 = max(600, 600, 600, 900, 600) = 900s ≈ 15分钟
```

#### 跨平台并行 + 多浏览器并发

```
PLATFORM_CONCURRENCY = {dy:3, bili:1, ks:2, toutiao:3, wb:1}

各平台耗时：
  dy: 100/3 = 34 × 6s = 204s
  bili: 100 × 6s = 600s
  ks: 100/2 = 50 × 6s = 300s
  toutiao: 100/3 = 34 × 9s = 306s
  wb: 100 × 6s = 600s

总耗时 = max(204, 600, 300, 306, 600) = 600s = 10分钟
(瓶颈: B站和微博各只有1个Cookie)
```

### 场景四：500条乱序（随机分布各平台）

假设分布为：dy=150, bili=80, toutiao=120, ks=80, wb=70

#### 仅跨平台并行

```
总耗时 = max(150×6, 80×6, 120×9, 80×6, 70×6) = max(900, 480, 1080, 480, 420) = 1080s ≈ 18分钟
```

#### 跨平台并行 + 多浏览器并发

```
PLATFORM_CONCURRENCY = {dy:3, bili:1, ks:2, toutiao:3, wb:1}

总耗时 = max(50×6, 80×6, 40×9, 40×6, 70×6) = max(300, 480, 360, 240, 420) = 480s = 8分钟
```

## 速度瓶颈分析

1. **头条最慢**：需要完整加载页面 + DOM解析 + 二次确认，单条约9秒
2. **API型平台（抖音/B站/快手/微博）较快**：直接API调用，单条约5-6秒
3. **跨平台并行效果显著**：多平台场景下，总耗时 = 最慢平台耗时
4. **同平台并发受限于**：Cookie数量（需Cookie平台）、服务器内存、IP风控
