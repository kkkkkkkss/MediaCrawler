# 微博指标提取修复 — 原理逻辑说明

## 问题根因

### 1. 转赞评硬编码提取全返回 None

**数据流**：
```
WeiboClient.get_note_info_by_id()
  → 访问 m.weibo.cn/detail/{note_id}
  → 解析 $render_data[0].status
  → 返回 {"mblog": {status对象}}
```

原始 `fallback_field_map.py` 中微博的路径映射：
```python
"wb": {
    "praise_count": ["attitudes_count"],      # ← 在根级查找
    "reply_count": ["comments_count"],         # ← 在根级查找
    "share_count": ["reposts_count"],          # ← 在根级查找
}
```

但实际返回的 JSON 结构为 `{"mblog": {"attitudes_count": 3, ...}}`，字段被嵌套在 `mblog` 下。`_deep_get(raw_json, "attitudes_count")` 在根级找不到值，返回 None。

而 `author` 路径 `mblog.user.screen_name` 有 `mblog.` 前缀，所以作者提取正常。

### 2. 标题为空

微博 API 的 `title.text` 字段值为 `"公开"`（可见性标记），不是作品标题。微博没有独立的标题字段，内容在 `text_raw` 中。

## 修复方案

### 修改文件清单

| 文件 | 修改内容 |
|------|---------|
| `tools/fallback_field_map.py` | 修复 `wb` 路径映射 + 新增 `_extract_wb_title()` |
| `tools/ai_field_mapper.py` | `TARGET_FIELDS` 加入 `title` + AI prompt 更新 |
| `store/url_check_excel_store.py` | 新增标题列定义、提取函数、合并逻辑 |

### 修复1：路径映射加 `mblog.` 前缀

```python
"wb": {
    "praise_count": [
        "mblog.attitudes_count", "attitudes_count",   # mblog嵌套优先，直接格式兜底
        "mblog.like_count", "like_count",
    ],
    "reply_count": ["mblog.comments_count", "comments_count"],
    "share_count": ["mblog.reposts_count", "reposts_count"],
    "visit_count": ["mblog.reads_count", "reads_count", "mblog.play_count", "play_count"],
    "author": ["mblog.user.screen_name", "user.screen_name"],
}
```

同时保留无前缀路径作为兜底，兼容可能的直接 API 格式。

### 修复2：标题智能提取

新增 `_extract_wb_title()` 函数，按优先级从以下字段获取正文：
1. `mblog.text_raw` — 纯文本正文
2. `text_raw` — 兜底
3. `mblog.longText.content` — 长文本内容
4. `longText.content` — 兜底
5. `mblog.text` / `text` — HTML 格式（去标签后使用）

提取规则：
```
正文 → 有 re.search(r"【(.+?)】") → 取第一个匹配的括号内文字
正文 → 无【】匹配 → 截取前25字 + "..."
```

### 修复3：Excel 标题列集成

**新增函数** `_extract_title()` — 从 metrics 或原始 JSON 中获取标题。

**合并逻辑**（`merge_results_to_excel`）：
- 通过 `_TITLE_COLUMN_NAMES` 精确匹配标题列（`标题`/`作品标题`/`title`/`原文标题`）
- 当标题值属于 `_TITLE_EMPTY_PLACEHOLDERS`（`""`/`"-"`/`"\t-"`/`"无"` 等）时覆盖
- 有正常标题的行保留不动

**生成逻辑**（`generate_url_check_excel`）：
- `_COLUMNS` 列定义新增 `("title", "标题")` 列
- `_ENSURE_COLUMNS` 新增 `("标题", "title")` 确保合并时补列

### 提取策略流程图

```
[原始 JSON] → fallback_extract("wb", json)
                 ├─ mblog.attitudes_count → praise_count ✓
                 ├─ mblog.comments_count  → reply_count  ✓
                 ├─ mblog.reposts_count   → share_count  ✓
                 ├─ mblog.user.screen_name→ author       ✓
                 └─ _extract_wb_title()   → title        ✓

            → _metrics_insufficient(result)?
                 ├─ No  → 返回硬编码结果（0 AI 调用）
                 └─ Yes → 调用 AI 补充提取 → 合并结果
```

## 接口字段对照表

基于 `微博接口样例.md` 中的真实响应结构：

| 系统字段 | 微博字段路径 | 样例值 |
|---------|-------------|--------|
| praise_count | `reposts_count` (顶层) / `mblog.attitudes_count` (嵌套) | 3 / 26 |
| reply_count | `comments_count` / `mblog.comments_count` | 0 / 1 |
| share_count | `reposts_count` / `mblog.reposts_count` | 1 / 0 |
| visit_count | 微博文本贴无此字段 | null |
| author | `user.screen_name` / `mblog.user.screen_name` | "杭州地铁爱好者" |
| title | `text_raw` 提取 | "午夜突发，张小泉剪刀厂旧址起火" |
