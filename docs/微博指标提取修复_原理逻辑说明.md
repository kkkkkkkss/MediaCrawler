# 微博指标提取修复 — 原理逻辑说明

## 问题根因

微博移动端接口 `m.weibo.cn/detail/{mid}` 返回的 JSON 中，视频播放量的字段路径是：

```json
{
  "mblog": {
    "attitudes_count": 150,       // 点赞 ✓ 能提取
    "comments_count": 42,         // 评论 ✓ 能提取
    "reposts_count": 23,          // 转发 ✓ 能提取
    "page_info": {                // 视频信息（仅视频帖子有）
      "type": "video",
      "play_count": 7110000       // ← 播放量在这里
    }
  }
}
```

原硬编码路径只查找了 `mblog.reads_count` 和 `mblog.play_count`（顶层），没有查找 `mblog.page_info.play_count`（嵌套路径），导致视频播放量始终返回 `None`。

## 修复方案（两处改动）

### 1. 新增字段路径

在 `tools/fallback_field_map.py` 中微博的 `visit_count` 路径列表前面插入 `page_info.play_count`：

```python
"visit_count": [
    "mblog.page_info.play_count",   # ← 新增：视频播放量的正确路径
    "page_info.play_count",          # ← 新增：无 mblog 前缀的备选
    "mblog.reads_count",             # 原有：阅读量（较少出现）
    "reads_count",
    "mblog.play_count",
    "play_count",
],
```

### 2. 中文数字格式解析

微博部分接口返回的 `play_count` 可能是中文格式字符串（如 `"1.2万"`、`"53万播放"`），原 `_to_int()` 函数无法解析。

增强后的 `_to_int()` 处理流程：

```
输入值 → 是 int/float？直接返回
       → 尝试 int(val) 转换
       → 去掉中文后缀（"次播放浏览"）
         → 尝试 int(float(stripped)) 纯数字转换
         → 检查是否含 "万"/"亿" 单位 → 乘以 10000/100000000
       → 均失败 → 返回 None
```

## 数据流路径

```
url_check 调度 → _fetch_detail("wb", client, content_id)
  → WeiboClient.get_note_info_by_id(content_id)
    → GET m.weibo.cn/detail/{mid}
    → 解析 $render_data → {"mblog": status_object}
  → ai_mapper.extract_metrics("wb", raw_json)
    → fallback_extract("wb", raw_json)
      → _deep_get(raw_json, "mblog.page_info.play_count")  ← 现在能命中
      → _to_int(value)  ← 现在能解析中文数字
```

## 微博帖子类型与浏览量可用性

| 帖子类型 | page_info.play_count | reads_count | 实际可提取 |
|----------|---------------------|-------------|-----------|
| 视频帖子 | ✓ 有值（本次修复） | ✗ 通常无 | ✓ |
| 纯文字帖子 | ✗ 无 page_info | ✗ 移动端不提供 | ✗ |
| 图文帖子 | ✗ 无 page_info | ✗ 移动端不提供 | ✗ |
