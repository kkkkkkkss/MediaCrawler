# 同平台多浏览器并发 - 使用手册

## 功能概述

在批量爬取时，同一个平台可以同时启动多个浏览器，每个浏览器绑定不同的 Cookie（账号），实现同平台并发处理。对于不需要 Cookie 的平台（如头条），可以直接开多个空白浏览器并发处理。

---

## 配置说明

所有配置位于 `config/base_config.py`。

### 1. 每平台浏览器并发数

```python
PLATFORM_CONCURRENCY = {
    "dy": 1,        # 抖音：风控严格，默认1
    "bili": 1,      # B站：默认1
    "ks": 1,        # 快手：默认1
    "toutiao": 5,   # 头条：不需要登录，可多开
    "xhs": 1,       # 小红书：默认1
    "wb": 1,        # 微博：默认1
}
```

**实际并发数的计算规则：**

- cookie_free 平台（头条）：`min(配置值, URL数量)`
- 其他平台：`min(配置值, 可用Cookie数, URL数量)`

### 2. 每平台 URL 间隔时间

```python
PLATFORM_SLEEP_SEC = {
    "dy": 2,
    "bili": 2,
    "ks": 2,
    "toutiao": 1,   # 头条无登录限制，可更快
    "xhs": 2,
    "wb": 2,
}
```

### 3. 单 Cookie 处理上限（软上限）

```python
# 0 = 不限制（由共享队列自然均分）
MAX_URLS_PER_COOKIE = 0

# 示例：设为 50 表示每个浏览器最多处理 50 条 URL
# 达到上限后该浏览器停止，剩余 URL 由其他浏览器继续
MAX_URLS_PER_COOKIE = 50
```

### 4. 无 Cookie 平台列表

```python
# 这些平台直接开空白浏览器，不受 Cookie 数量限制
COOKIE_FREE_PLATFORMS = ["toutiao"]
```

## 并发值推荐


| 服务器内存 | 头条 (无Cookie) | 其他严格平台 (有Cookie) |
| ----- | ------------ | ---------------- |
| 4GB   | 2            | 1                |
| 8GB   | 3~4          | 1~2              |
| 16GB+ | 4~5          | 2~3              |


**注意事项：**

- 每个 Playwright 浏览器实例约占 200~400MB 内存
- 跨平台并行也在同时运行（5个平台各2个浏览器 = 10个浏览器 = 约 2~4GB）
- 建议留出系统和其他进程的内存空间

## 后续如何为其他平台开启多账号并发

### 前提条件

1. Cookie 池中该平台有多个有效 Cookie（多个账号）
2. 了解该平台的风控强度

### 配置步骤

以抖音为例，假设 Cookie 池中有 3 个抖音账号：

```python
# 1. 修改并发数
PLATFORM_CONCURRENCY = {
    "dy": 3,        # 开 3 个浏览器
    ...
}

# 2. 可选：调整间隔时间
PLATFORM_SLEEP_SEC = {
    "dy": 3,        # 抖音风控严格，间隔可稍长
    ...
}

# 3. 可选：设置单账号处理上限
MAX_URLS_PER_COOKIE = 30   # 每个账号最多处理 30 条
```

### 验证

观察日志中出现多个 Worker 标识：

```
[W1-dy] 启动成功, Cookie=dy_01
[W2-dy] 启动成功, Cookie=dy_02
[W3-dy] 启动成功, Cookie=dy_03
[W1-dy] 处理 id=1 url=...
[W2-dy] 处理 id=2 url=...
[W3-dy] 处理 id=3 url=...
```

## 使用场景

### 场景一：纯头条批量检测

头条不需要 Cookie，直接多开浏览器：

```python
PLATFORM_CONCURRENCY = {"toutiao": 4}
PLATFORM_SLEEP_SEC = {"toutiao": 1}
```

### 场景二：混合平台（多平台各开多浏览器）

```python
PLATFORM_CONCURRENCY = {
    "dy": 2,
    "bili": 2,
    "toutiao": 4,
    "ks": 2,
    "xhs": 1,
    "wb": 1,
}
```

### 场景三：大批量任务 + 单账号保护

500条链接，5个平台，每个账号不超过30条：

```python
PLATFORM_CONCURRENCY = {"dy": 3, "bili": 2, "toutiao": 4, "ks": 2, "wb": 1, "xhs": 1}
MAX_URLS_PER_COOKIE = 30
```

## Cookie 失效处理

当某个浏览器的 Cookie 失效时：

1. 系统尝试从 Cookie 池中获取一个新的、未被其他 Worker 占用的 Cookie
2. 如果有可用 Cookie → 重建浏览器和 Client，继续处理
3. 如果无可用 Cookie → 该 Worker 停止，剩余 URL 留在共享队列由其他 Worker 消费

## 关闭并发

如果遇到问题需要回退到单浏览器模式，将所有平台并发数设为 1：

```python
PLATFORM_CONCURRENCY = {
    "dy": 1, "bili": 1, "ks": 1, "toutiao": 1, "xhs": 1, "wb": 1,
}
```
