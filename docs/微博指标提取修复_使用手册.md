# 微博指标提取修复 — 使用手册

## 修复概要

本次修复解决了微博（wb）平台在 url_check 模式下的两个核心问题：

1. **转赞评指标硬编码提取失败** → 修复后硬编码直接提取，不再需要 AI 调用
2. **标题列为空或显示占位符** → 自动从正文中智能提取标题

## 使用方式

### 无需额外配置

修复对现有使用流程**完全透明**，无论你通过以下哪种方式使用 url_check，微博链接均自动受益：

- **API 单链接检测**：`POST /api/v1/check/url`
- **API 文件上传检测**：`POST /api/v1/check/upload`（支持 `.xlsx/.csv/.txt`）
- **API 批量链接检测**：`POST /api/v1/check/batch`
- **命令行模式**：`uv run python main.py --platform wb --type url_check`

### 指标提取结果

对微博链接，硬编码提取器现在能正确返回以下字段：

| 字段 | 对应微博接口字段 | 说明 |
|------|-----------------|------|
| `praise_count` | `attitudes_count` | 点赞数 |
| `reply_count` | `comments_count` | 评论数 |
| `share_count` | `reposts_count` | 转发数 |
| `visit_count` | `reads_count` / `play_count` | 阅读/播放数（微博文本贴通常无此字段） |
| `author` | `user.screen_name` | 作者昵称 |
| `title` | 从 `text_raw` 生成 | 智能提取标题 |

### 标题提取规则

微博没有独立标题字段，系统按以下规则自动生成：

1. **有 `【xxx】`**：取括号内文字作为标题
   - 例：`【午夜突发，张小泉剪刀厂旧址起火】4月27日...` → `午夜突发，张小泉剪刀厂旧址起火`
2. **无 `【】`**：截取正文前 25 字 + `...`
   - 例：`真的看得人心惊又心寒！谁都想不到...` → `真的看得人心惊又心寒！  谁都想不到一场惨烈事故，...`

### Excel 合并行为

上传 Excel 文件时，系统会自动识别标题列（支持列名：`标题`、`作品标题`、`title`、`原文标题`），并在以下情况填充：

- 标题为空
- 标题为占位符：`-`、`\t-`、`—`、`无`、`无标题`、`null`、`/` 等

已有正常标题的行不会被覆盖。

### 提取模式

通过 `.env` 中的 `URLCHECK_EXTRACT_MODE` 控制（默认 `hardcode_first`）：

| 模式 | 说明 |
|------|------|
| `hardcode_first` | 硬编码优先，指标不足时 AI 补充（推荐） |
| `hardcode_only` | 仅硬编码，不调 AI |
| `ai_only` | 仅 AI 提取 |
